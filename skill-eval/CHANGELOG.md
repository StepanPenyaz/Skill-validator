# Changelog

## [1.4.0]

- The model recommendation is now the highest similarity per dollar (`similarity / cost`), the metric shown in the "Similarity points per $" column. It replaces "within a tolerance of the best similarity, then the cheapest".
- Similarity in the recommendation is the mean over all runs of the model, a failed run or missing case counting as 0 (the "All runs, missing = 0" column of `05_similarity.md`), not the mean over complete runs only.
- Stability no longer excludes a model from the recommendation; it is reported next to it. A model is dropped only when it has no similarity or cost, or when both judges say `Major gaps`. When no model is stable, the report says the problem is probably in the skill.
- `recommendation.tolerance_points` is removed from `config.yaml`.

## [1.3.0]

- New profile `codebase-plan` for skills that investigate a codebase and write an implementation plan, often through subagents. Needs a sandbox in the skill's `evals/sandbox/` (`codebase/` and `agents/*.md`). Similarity = 0.55 file recall + 0.20 grounding + 0.25 structure (phases present, same layers touched). See `references/profiles.md`, section 3a.
- Profile hook `prepare(workdir, skill_dir, case_path)`: fills the clean working directory before a run. `run_skill.py` calls it; the default does nothing, so `document` is unchanged.
- The profile contract test no longer requires `check_applicable(".")` to succeed: a profile may refuse a skill, with a reason.
- Example data for `skill-examples/feature-analyst/evals/` (sandbox, four inputs, four verified plans), generated and marked in `evals/GENERATED.md`.

## [1.2.0]

- Model runs are `claude -p` processes started by `scripts/run_skill.py`, one per model, repeat and input, in a clean project that holds the skill but not `evals/`. Real tokens (input, output, cache), real cost, time, turns, tool calls and the full transcript are saved per case. Repeats: `runs_per_model` in `models_config.yaml`.
- Stability is measured on repeats of the same input. Models are `stable`, `unstable`, `insufficient` (too few complete runs) or `single run`. Two or more unstable models raise a possible skill problem flag.
- A case without output scores 0 and makes its run incomplete. Such runs no longer drop out of the average unnoticed.
- The recommendation tolerance is the run-to-run spread of the models still in the race (never below `recommendation.tolerance_points`). Unstable and insufficient models are not recommended.
- Two independent judges write the verdict for each model's median run. `Major gaps` from both drops the model; a disagreement is `Disputed` and flagged.
- Profiles: everything that depends on the kind of skill (verified outputs, prompt and tools, output collection, scoring, applicability) is a profile, `scripts/profiles/<name>.py` plus `profiles.<name>` in `config.yaml`. The text behaviour is the `document` profile, moved unchanged. `--profile` on `run_skill.py` and `compute_similarity.py`; `references/profiles.md` explains how to add one.
- All settings are in one file, `config.yaml`. It replaces `references/models_config.yaml`, `severity_config.yaml`, `similarity_config.yaml` and `rubric-review-session.md`. The unused `pricing` table is gone (cost comes from `claude -p`); the static check severities are under `static_checks`.
- The request given to the models is `runner.prompt` in `config.yaml`. Per-skill `evals/run.yaml` and `evals/similarity.yaml` are not supported.
- Step order: structure check (gate), rubric review, evaluation data, runs, comparison and similarity, reports.
- The structure check is a gate: Blocker findings stop the evaluation (`generate_static_report.py --fail-on-blocker`, exit code 2).
- Missing `evals/` data is generated by a subagent and marked in `evals/GENERATED.md`. The reports say the data needs review.
- Two reports: `final_report.md` (Summary, Skill name, Skill description, Model recommendation, and the blocking findings when there are any) and `detailed_final_report.md` (everything, plus section 9, run stability and behaviour). `--baseline` reads `detailed_final_report.md`.

## [1.1.0]

- Output similarity: `scripts/compute_similarity.py` scores each produced output against its verified output (0 to 100%), per case and per model. Written to `step_reports/05_similarity.md`.
- Similarity is defined per kind of skill. Profiles live in `references/similarity_config.yaml`; the `document` profile is implemented. See `references/similarity-profiles.md`.
- The comparison step now ends with a `Verdict:` line (Equivalent, Minor gaps, Major gaps).
- `final_report.md` has a new section 8, Model recommendation: a table of similarity, verdict, tokens, time and cost, and the recommended model chosen by a fixed rule. The tolerance is `recommendation.tolerance_points` in `references/models_config.yaml`.
- The summary names the recommended model. Section 5 shows similarity per case.
- Rule change: the skill still gets no numeric score; similarity scores outputs only.

## [1.0.0]

- Evaluation flow: structure check, rubric review, runs on several models, final report.
- `/skill-static-review` command: structure check with no Claude session.
- Each Claude step runs in its own subagent with a clean context.
- Each model run reports measured tokens, time and cost in `run_on_<model>_report.md`.
- `final_report.md` has numbered sections. With two versions it adds V1/V2 columns and charts.
- Reports are Markdown only.
